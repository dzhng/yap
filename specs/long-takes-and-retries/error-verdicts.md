# Error verdicts

Audit contract for slices 04–06 and 12. This is a decision artifact, not a second runtime
registry. Slice 05 applies these verdicts to the existing ledger; this slice only extends
its scan to `apps/macos/Sources`, refreshes exact per-file counts and classifies new literals.
No existing ledger category or retryable bit is changed here.

**Rule:** non-retryable means the identical request can never succeed: invalid parameters,
a nonexistent reference or a deleted owner. Our files, implementation and machine are
repairable. Cancellation is retryable. Retryable does not promise success without repair
and never authorizes an automatic retry or a new capture.

`true` / `false` are proposed retryability. `—` means a non-error token, with no retry
policy. Category is the scanner ledger’s category today, not a new category taxonomy;
several diagnostics are historically `issue-code` even when thrown. `DOMAIN_MIN` and
`DOMAIN_MAX` are file-format tokens despite that category. `L` is today’s ledger bit;
`H` is the capture helper’s computed bit, shown only for literal CaptureFailure producers
or its explicit denylist. The helper formula is at
`helpers/mac/Sources/YapCapture/CaptureTypes.swift:160`.

Producer anchors identify emitting owners and relevant propagation sites, not every
comparison, declaration or consumer literal counted by the scanner. Shared validator
anchors stand for their callers. Every row cites source; policy conclusions (including
whether repair can make a retry succeed), proposed codes, delay values and app treatments
are **inferences / audit decisions**, not measured executions. No user library or recording
was inspected. Only NOT_READY’s 15 000 ms is prescribed by the slice; using that same delay
for the other wait codes is an **inference**, a simple advisory cadence, never a scheduler.
Execution errors need no guessed cooldown (`—`); permission/configuration failures need a
fix action rather than a timer. No transient error implies that the earlier mutation was
rolled back: preserve its durable request identity.

## Required splits and application rules

These are **decisions for later slices**, not changes made by this audit. Reuse the existing
ledger codes named here. Only the three proposed codes in the table need new vocabulary;
`JOB_INTERRUPTED` already exists in SQL. Assign by provenance at the boundary that knows
whether data was supplied by the caller or generated by Yap. Do not make a shared reader
infer provenance from filenames or error-message text, and do not give a code two bits.

### Evidence: retain a retry for our own recordings

Keep `INVALID_EVIDENCE=true` for our capture journals, normalized evidence, retained indexes,
compiler outputs and generated inference operands. The 64 KiB line refusal is
`packages/core/src/evidence.ts:380`, through its producer at `:130`. This is the origin
failure’s retryability verdict; it does not claim the origin take was inspected or fixed.

There is caller input: `apps/service/src/project-service.ts:1277` passes the public
correspondence request into `admitCorrespondence`, whose accepted-measurement checks emit
`INVALID_EVIDENCE` at `packages/core/src/correspondence.ts:37` and `:42`. Move those checks
to `INVALID_INPUT_EVIDENCE=false`. A supplied invalid correspondence receipt fingerprint
(`packages/core/src/correspondence.ts:64`) uses that same input code when admitting caller
receipts; corruption of our retained receipt stays `INVALID_EVIDENCE=true`.

Caller-package validation must similarly translate malformed supplied evidence to
`INVALID_INPUT_EVIDENCE=false`, while leaving our own re-export/writer/read failures
retryable. The portable metadata validator emits at `packages/core/src/evidence-pages.ts:124`
and `:134`; the shared record reader emits through `packages/core/src/evidence.ts:130`.
The latter is also used on native-generated normalized output during package verification
(`packages/core/src/source-admission.ts:84`, `:113`), so do **not** globally relabel all
reader failures as caller fault just because an import initiated the work. A mismatch with
the caller’s declared immutable package receipt is already `INVALID_PACKAGE` at
`packages/core/src/source-admission.ts:107`. Keep that false for malformed supplied packages.
The same boundary rule applies to malformed supplied journals/media: input failures use
INVALID_INPUT_EVIDENCE or INVALID_PACKAGE, while INVALID_JOURNAL, INVALID_MEDIA and
PACKED_MEDIA_INVALID stay retryable for our files. This provenance routing is an
**inference** from these production paths, not a new reader.

### Readiness: waiting is different from a missing implementation reference

Keep `NOT_READY=true, retryAfterMs=15000` only for work whose readiness can change:
cache reconciliation (`packages/core/src/cache.ts:140`), evidence preparation
(`packages/core/src/alignment-evidence.ts:387`, `packages/core/src/speaker-evidence.ts:566`),
and import completion (`packages/core/src/recording-prompt.ts:178`). A failed dependency
requires an explicit retry of that dependency; a readiness read never starts it again.

A retained recipe whose exact implementation ID no longer matches the available one gets
`PINNED_IMPLEMENTATION_UNAVAILABLE=false`. The five families required by the slice are
`packages/core/src/frame-inspection.ts:981`, `packages/core/src/project-preview.ts:144`
and `:254`, `packages/core/src/index-processing.ts:337`,
`packages/core/src/audio-inspection.ts:606`, and `packages/core/src/acoustic-inspection.ts:767`.
Apply the same rule to all pin comparisons in those audio/acoustic owners, including
`packages/core/src/audio-extraction.ts:232`, and to native bound implementation comparisons
(`helpers/mac/Sources/YapAudio/CompositionRetime.swift:10`,
`helpers/mac/Sources/YapAudio/CompositionState.swift:90`,
`helpers/mac/Sources/YapFrames/LUTColor.swift:28`,
`helpers/mac/Sources/YapFrames/SDRCorrection.swift:36`). A missing current runtime/adapter
without a vanished immutable pin is our capability problem: `PREREQUISITE_MISSING=true`,
not a permanent missing reference. Absence of a required binding from an internally built
plan is `INTERNAL_ERROR=true`; a caller omitting a required parameter is `INVALID_PARAMS=false`.
This distinction preserves the rule that our code and installation remain repairable.

The export retry branch at `apps/service/src/exports.ts:984` currently recognizes
`NOT_READY` by implementation ID. Update that consumer when applying the split: a vanished
pin cannot be made retryable by that branch. Preserve the old intent and explain that the
caller must explicitly request fresh work with a current implementation; never silently
re-pin its saved export or start a new recording.

Other current `NOT_READY` sites are not waiting. Route unknown video profiles
(`helpers/mac/Sources/YapFrames/CompositionFrameRenderer.swift:45`) and unsupported
service-local package/read selections (`apps/service/src/project-service.ts:1292`, `:2032`,
`:2894`) to `INVALID_PARAMS=false`. An empty selected audio tap
(`packages/composition/src/compiler.ts:293`, `packages/composition/src/processing-state.ts:172`)
uses `INVALID_RANGE=false`; an already-ready transcript with no selected words
(`apps/service/src/project-service.ts:3226`) uses `INVALID_PARAMS=false`. Missing declared
physical support (`apps/service/src/join-verification.ts:237`) uses
`UNAVAILABLE_SUPPORT=false`. Internal numeric capacity or unsupported current native
execution (`helpers/mac/Sources/YapMedia/ExactTime.swift:94`,
`helpers/mac/Sources/YapAudio/CompositionRetime.swift:38`,
`helpers/mac/Sources/YapFrames/CompositionPictureExecutor.swift:970`) stays retryable under
`LIMIT_EXCEEDED` or `PREREQUISITE_MISSING`, respectively, without claiming a timed wait will
repair it. The app’s Export Retry without a job (`apps/macos/Sources/Yap/ExportController.swift:134`)
