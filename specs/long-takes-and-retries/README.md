# Long takes and honest retries

A take records fine, then fails to import because one ⇧ stroke wrote a journal line longer
than the importer reads. The failure is filed as permanent, nothing offers a real retry, and
the app's Retry button starts a new recording. This spec fixes that class of failure: limits
come from stated requirements instead of guesses, every failure says whether and how to
retry it, and nothing a user recorded is lost or hidden behind an error.

[MAP.md](MAP.md) is the discovery record: every decision with its reason, the landmine sweep,
and the user's answers. This README is the build plan; where they differ, this README wins.

## Requirements

The user states two limits. Everything else is derived from them or deleted.

| Requirement | Value |
|---|---|
| Longest take | 12 hours of recorded time (pauses excluded); capture ends the take cleanly there |
| Longest ⇧ stroke | 5 minutes; a stroke still held at 5 minutes is committed and a new one begins |

Every other size, count or time bound is `growth rate × requirement × stated margin`, with the
derivation written beside the constant. A bound that can't be derived is deleted. Readers
stream; a bound distinguishes corrupt input from valid input, it never caps what a valid take
can hold.

Product outcomes:
- A 12-hour take records, publishes, imports, plays, gets a prompt and can be edited.
- Copy prompt and ⌥⇧V never wait and never refuse for a take that exists.
- Every failure says whether it can be retried, when, and with which call.
- Nothing retries a failure on its own; a person or agent asks.
- Every error the app shows carries its action, or the situation is prevented or shown as
  status text instead.

Non-goals: rollback (an older app opening a library this version wrote, beyond refusing
schema-4 journals clearly), new relaunch machinery, reducing `pcmAppend` volume unless slice 00
shows a derived budget needs it, changing what the yap skill tells agents to do beyond the paste
section and retry fields.

## Contracts

| Contract | Owner | Change |
|---|---|---|
| Take and stroke requirements | `packages/protocol` (new `requirements` module + JSON) | new; Swift mirrors checked by test |
| Error envelope | `operationErrorSchema`, `packages/protocol/src/index.ts` | optional `retryAfterMs`; `details.retry: {operation, params}` |
| Retryability, retry delay, plain cause | `packages/protocol/src/refusal-ledger.json` | per-code `retryable`, optional `retryAfterMs`, `cause` |
| Job retryability | `packages/core/src/jobs.ts` | read from the error code; stored bit unread |
| Journal format | Swift `CaptureJournal` + TS `evidence.ts`, one capability table each | schema 4: cursor sampling fields, change-only samples, bounded strokes |
| Take summary | `CapturePublishedSource` / `capture-publication.ts` | optional take kind and marks presence, new takes only |
| `recording.prompt` | `packages/core/src/recording-prompt.ts` | facts from capture only; never refuses an existing take; no data lists |
| `cursor.raw` | `packages/core/src/capture-source-read.ts` | a page may begin with the sample in force at its start |
| `recording.get --wait` | `apps/cli/src/wait.ts` | pending while recording, finalizing or importing |

Data compatibility (the only compatibility carried): existing takes play, prompt and edit;
schemas 1–3 read as before, with a missing sampling field meaning 60 Hz and every tick
written; old journals re-export byte-for-byte so old packages import; new takes write schema 4
so an older app refuses them clearly. App, service, CLI and bundled skill ship together.

## One owner per concept

The end state must read as designed today. Each concept has one owner; the slice that
introduces the owner deletes the predecessor in the same change.

| Concept | Owner | Deleted predecessors |
|---|---|---|
| Retryability | ledger, looked up by code everywhere (`refusalRetryable`, SQLite `ledger_retryable`) | helper denylist `CaptureTypes.swift:160`; hand-set `retryable` literals in the service and Swift app; job-row and finalization-error stored bits as read sources |
| Retry delay and plain cause | ledger entry | none exist yet; no per-site constants |
| Resolving call | one service adapter rule plus the job projection | none |
| Requirements and derived bounds | `packages/protocol` requirements module | the `65536`, `1_048_576`, `268_435_456` and count literals the limits audit lists |
| Journal line reading | one linear reader per language (`CaptureJournal.readRecords`, TS `evidence.ts` via the protocol JSON-line owner) | per-chunk rescans; TS-only 64 KiB checks |
| Journal capabilities by schema | one table per language | scattered `== 3`, `[1,2,3]` checks |
| Stroke bound | `MarkRecognizer` ends a stroke at 5 minutes | `CaptureJournal.recordMark` point thinning |
| Cursor sample semantics | header sampling fields + `CursorTrack` | batch-of-30 flush; sample-count trail caps |
| Take facts before import | take summary | none; the prompt stops reading the acquisition for these facts |
| App failure with action | one scoped failure value in `ControlsState` | `failure: String?`; capture-panel Retry (`RecordingControls.swift:1210`) |
| Automatic failure retries | none: retries are explicit | transcript backlog retry counter; startup re-attempt of failed finalization |

No slice may add a compatibility layer, a second reader, or a parallel constant. Transitional
scaffolding is not planned; if a slice needs some, name it in the slice with the slice that
removes it.

## Firewalls

- Development never edits a user's recordings or library. Synthetic and fixture takes only.
- No editorial behaviour: nothing decides what content means; marks, prompts and errors describe.
- The prompt names no operations except the closing pointer to the yap skill (D2/D3′).
- Retry is explicit. No read, poll, wait or startup path re-runs a failed job.
